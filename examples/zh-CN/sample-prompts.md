# 示例提示词

[English prompts](../en/sample-prompts.md) · [说明性设计](code-generation-review-fix.md)

这些提示词假定已经安装中文 Skill `agent-system-design-cn`。它们说明 Skill 准备接受的请求类型，不是咒语，也不会产生实测分数。

## 1. 新设计，把更简单的档位留在判断里

```text
使用 agent-system-design-cn。设计一个系统：把一份简短的产品 FAQ 变成带出处的回答，交给客服人员使用。

从需求开始。在提示词、工作流、单 Agent、多 Agent 之间选择，并说明每个更简单的选项为什么够或不够。如果普通代码就够，就停在那里。

按 Skill 的设计文档模板交付。不要部署，不要修改仓库，不要编造自检分数。没有核实的内容标成待确认。
```

## 2. 质疑 Agent 的数量

```text
使用 agent-system-design-cn。我想要五个 Agent：规划者、研究员、编码员、测试员和管理者，用来给一个 Python 文件增加单词计数函数。

判断这种拆分是否成立。优先使用能够满足需求的最简档位。如果保留一个以上的角色，写明是哪一种上下文、工具或权限隔离使其必要。交付设计文档，不要交付代码，也不要交付一条正在运行的流水线。
```

## 3. 评审已有设计

```text
使用 agent-system-design-cn。评审下面这份设计。不要把它改写成一个新系统。

只输出《Agent 设计评估报告》。开头写你实际能看到的现状，以及仍然缺的材料。只选择适用的维度。无法检查的维度不要填分数，也不要把文档分数当成可以发布的许可。

设计：
- 一个 Agent 同时拥有仓库、shell 和生产数据库。
- 它写代码、跑测试，并自己判定测试通过。
- 没有停止条件，也没有单独的审查。
```

## 4. 要求示例中的流程，但不要把示例当成结果

```text
使用 agent-system-design-cn。为下面的规格设计一条固定的「先生成，再审查，再修复」流程：

实现 word_counts(text: str) -> dict[str, int]。文本先转成小写。一个单词是一段连续的 Unicode 词字符。标点不计入单词。空字符串和只有标点的输入返回空字典。

宿主必须校验交接。审查者必须看到原始规格和确切的代码版本，并且不能看到编写者的草稿笔记。不要执行候选代码。按 Skill 的设计文档模板填写。除非你真的运行了检查，否则自检分数留空，并把设计标为说明性的。
```

本仓库为提示词 4 填好的示例是 [code-generation-review-fix.md](code-generation-review-fix.md)。它演示的是格式和取舍，不是可以当作实测性能粘贴的结果。
